[파스토 목록 갱신 - 평일 08:30·11:30·14:30 KST 예약 작업, 하루 한 번만 갱신]
맨 먼저 오늘(한국 날짜) logistics_fassto_sync 기록이 있는지 select로 본다. 있으면 "오늘 이미 갱신함"만 남기고 끝낸다.
알림은 슬랙 이상윤 본인 DM으로만 보낸다. 성공하면 보내지 않는다.
작업 폴더: entropysales-dashboard 저장소(main 최신). 절차는 LOGISTICS.md의 "파스토 목록 갱신"과 같다.
node_modules/xlsx가 없으면 먼저 npm ci 를 실행한다.
아래 어느 단계든 막히면(다운로드가 안 되거나 FMS가 로그인 화면이면 포함) 아무것도 바꾸지 말고 사용자에게 알리고 끝낸다.
옛 SQL 파일이 실행되지 않도록, 시작할 때 <스크래치 폴더>/fassto-stock.sql 을 먼저 지우고(없으면 그대로), 중간에 멈출 때마다 그 파일을 다시 지운다.

1. 브라우저로 https://fms.fassto.ai 상품별재고현황 화면을 열어 엑셀로 내려받는다.
   로그인이 풀려 있으면 아무것도 바꾸지 말고 탭을 닫고 끝낸다. 알림은 시각에 따라 다르다.
   - 11시 전(1차): "FMS 로그인이 풀려 있어요. 크롬에서 FMS에 로그인해 두시면 11:30·14:30에 다시 시도할게요." DM
   - 11시~14시 전(2차): DM 없음(1차에 알림)
   - 14시 이후(3차): "오늘은 FMS 로그인이 없어 갱신하지 못했어요. 목록은 <마지막 갱신 시각> 기준이에요." DM
   로그인 말고 다른 이유로 멈추면 몇 번째 시도든 이유를 DM 한 통으로 알린다.
   비밀번호·인증번호는 입력하지 않는다.
2. node tools/fassto-stock-json.cjs "<내려받은 파일>" --sql > "<스크래치 폴더>/fassto-stock.sql"
   - 필수 열을 못 찾았다는 오류면 실행하지 말고 오류 문구를 사용자에게 알린다.
   - 상품코드·바코드가 숫자 칸이거나 수량·날짜가 잘못됐다며 거부하면 아무것도 바꾸지 말고 그 문구를 사용자에게 알린다.
   - 화면(stderr)의 "로트 행 N개, 상품 M종"에서 N과 M을 적어 둔다.
3. 실행 전 확인(비우기 전에 한다). Supabase MCP execute_sql로 아래 하나만 실행한다.
   select row_count from public.logistics_fassto_sync where kind_code='stock' order by synced_at desc limit 1;
   - N이 돌려받은 row_count의 절반보다 적으면 아무것도 실행하지 않고 두 숫자를 사용자에게 알린 뒤 끝낸다(4단계로 가지 않는다).
   - 돌려받은 행이 없으면(첫 갱신) 이 확인을 건너뛴다.
4. 그 sql 파일을 읽어 select 문 하나만 실행한다(Supabase MCP execute_sql, postgres 권한, 쿼리 하나로. anon·authenticated는 실행할 수 없다). 다른 SQL은 실행하지 않는다.
5. select synced_at, row_count from public.logistics_fassto_sync where kind_code='stock' order by synced_at desc limit 1; 로 row_count가 N과 같은지 확인한다.
   N과 다르면 자동으로 다시 실행하지 말고 두 숫자(N, row_count)를 사용자에게 알린다.
   같으면 "파스토 목록 갱신: 로트 N행, 상품 M종"을 한 줄로 남긴다(M은 2단계 화면에서 가져온다).
6. 내려받은 파일과 SQL 파일을 지운다(5단계에서 숫자가 달랐어도 지운다). 저장소에는 아무것도 커밋하지 않는다.
