# 물류 요청: 파스토 배송신청 양식 자동 생성 설계 (2026-11-20)

## 1. 목적

회사의 출고 신청은 파스토 FMS 업로드 양식 3종으로 한다. 지금 물류 요청은 요약 칸(수량 요약·특이사항)만 받아서, 담당자가 양식 엑셀을 매번 손으로 만든다. 요청자가 받는 곳과 품목을 칸으로 입력하면, 요청 상세에서 해당 파스토 양식 엑셀을 바로 내려받게 한다. 품목은 파스토에 실제로 있는 상품코드로만 고르게 해 업로드 실패를 줄인다.

결정 사항(사용자, 2026-11-20):
- 받는 곳·품목은 요청자가 요청할 때 입력한다.
- 운송 방식으로 양식을 정한다: 택배 → 택배신청, 해외특송 → 해외택배신청, 직납·Air·Ocean → 차량배송신청(상품), 퀵·기타 → 양식 없음.
- 품목은 파스토 상품 목록에서 고른다. 목록은 Claude가 FMS에서 조회해 갱신하고, 나중에 파스토 API를 받으면 서버 자동 갱신으로 바꾼다.
- 품목은 DB에 저장하고, 엑셀은 내려받을 때 브라우저에서 만든다.
- 받는 곳 정보는 요청자와 물류 담당자만 본다.

범위 밖: 파스토로 직접 출고 접수(업로드 자동화), 파스토 API 연동 자체, 페이지 안의 엑셀 업로드 기능.

## 3. 데이터

### 3.1 파스토 상품 목록 `logistics_fassto_stock`

FMS '상품별재고현황'의 로트별 행. 갱신할 때 전체를 지우고 새로 넣는다(한 트랜잭션).

| 칸 | 내용 |
|---|---|
| product_code text | 파스토 상품코드 (문자, 앞자리 0 유지) |
| barcode text | 상품바코드 |
| product_name text | 파스토 상품명 |
| kind_text text | 상품구분(본품·사은품·부자재) |
| lot_text text | LOT번호 |
| expires_on date | 유통기한 |
| available_qty integer | 출고 가능 수량 |

갱신 기록 `logistics_fassto_sync`(한 행 이상, 최신만 사용): synced_at, source_text('fms-browser' 또는 나중에 'fassto-api'), row_count, note_text.

읽기: 회사 구성원. 쓰기: 서버 함수 `approval_private.logistics_replace_fassto_stock(rows jsonb, source text)`만. 이 함수는 SQL 편집기·Claude(서비스 역할)에서만 실행하고 anon·authenticated에는 실행 권한을 주지 않는다.

### 3.2 받는 곳 `logistics_request_recipients` (요청당 0~1행)

name_text, phone_text, postal_text, country_code(해외, 예 CH), state_text, city_text, district_text, address1_text(택배 기본주소/해외 상세주소), address2_text(택배 상세주소), email_text, tax_id_text, courier_text(해외 운송사), incoterms_code, currency_code, sender 덮어쓰기 칸(sender_name_text, sender_phone_text, sender_address_text, sender_email_text, 비우면 기본값).

RLS: 요청자 본인 또는 활성 담당자만 읽기·쓰기. 요청이 닫히면(shipped·canceled) 요청자는 못 고친다. 운송사·Incoterms는 담당자만 바꾼다(트리거로 검사).

### 3.3 품목 줄 `logistics_request_items`

request_id, line_no, product_code(필수), product_name_text(고를 때의 이름 복사), qty(1 이상), lot_text·expires_on(지정 출고일 때만), en_name_text, weight_kg numeric, unit_price numeric, hs_code_text. 한 요청당 최대 50줄.

RLS: 읽기는 회사 구성원(품목은 개인정보가 아님). 쓰기는 요약 수정 규칙과 같다: 요청자는 requested 상태에서만, 담당자는 shipped·canceled 전까지.

### 3.4 요청 표 변경

`logistics_requests.fassto_order_no text` — 요청 생성 때 트리거가 `LG날짜_순번`(예 `LG20261120_003`, KST 날짜, 그날 순번)으로 채운다. 문자 `- _`만 쓴다. 양식 종류는 저장하지 않고 운송 방식에서 계산한다.

## 5. 화면

### 5.1 새 요청 창

- 운송 방식을 고르면 양식이 정해지고 안내 한 줄이 보인다("파스토 택배신청 양식으로 만들어요").
- 양식이 있으면 '받는 곳'과 '품목' 묶음이 나타난다.
  - 택배: 받는 분, 전화, 우편번호, 기본주소, 상세주소.
  - 해외특송: 받는 분, 전화, 이메일, 국가코드, 주, 시, 구, 상세주소, 우편번호, (해당 국가면) 신분번호, 화폐. 운송사·Incoterms는 담당자가 상세에서 정한다.
  - 차량배송: 받는 곳 칸 없음(도착지는 특이사항).
- 품목: 상품명이나 바코드로 파스토 목록을 검색해 고르고 수량을 적는다. 같은 상품의 로트가 여러 개면 기본은 "로트 지정 안 함", 필요하면 로트를 고른다(유통기한이 함께 들어감). 출고 가능 수량(로트 지정 시 그 로트, 아니면 합계)보다 많으면 노란 경고만 한다. 해외는 줄마다 단가(필수)·무게·영문명을 적을 수 있다.
- 파스토 목록 갱신 시각을 보여주고, 2일 넘게 지났으면 "재고 정보가 오래됐어요"를 표시한다.
- 저장 순서: 요청 → 받는 곳 → 품목. 받는 곳이나 품목 저장이 실패하면 "요청은 올라갔고 품목은 저장하지 못했어요. 상세에서 다시 입력해 주세요"라고 알린다(지금 첨부 실패 처리와 같은 방식).

### 5.2 요청 상세

- '받는 곳' 칸(볼 권한이 없으면 "요청자와 물류 담당자만 볼 수 있어요")과 '품목' 표.
- 담당자: 해외특송이면 운송사(FEDEX 등 파스토 운송사 이름)·Incoterms·발송인 정보를 정하는 칸.
- **파스토 양식 내려받기** 버튼(양식이 있는 운송 방식일 때). 누르면 필수 칸 검사 → 통과하면 `파스토_<양식>_<주문번호>.xlsx` 저장. 실패하면 빠진 칸 목록을 창 안에 보여주고 내려받지 않는다.
- 받는 곳·품목 수정은 요약 수정과 같은 권한·상태 규칙.

## 6. 엑셀 생성 (`fassto-forms.js`, UMD)

- `FORMS`: 양식별 1~4행 원본 값과 열 목록(원본 파일에서 옮긴 상수).
- `formFor(ship_mode_code)` → 'overseas' | 'parcel' | 'vehicle' | null.
- `validate(form, request, recipient, items)` → 빠진 칸 목록(한국어 문장 배열).
- `buildRows(form, request, recipient, items, defaults)` → 5행부터의 2차원 배열.
- `toWorkbook(form, rows)` → SheetJS 워크북(시트 이름은 원본과 같게, 상품코드·주문번호·우편번호·전화 칸은 문자 셀).
- 대시보드에 이미 있는 SheetJS 0.18.5(`XLSX`)를 쓴다. 새 라이브러리 없음.

## 7. 오류 처리

- 상품코드는 항상 문자로 저장·출력(앞자리 0 유지).
- 주문번호·이름의 금지 문자는 내려받기 전에 검사한다(택배 받는 분: `( ) , - _` 외 특수문자 금지, 주문번호: `- _`만).
- 목록에 없는 상품코드(목록 갱신 후 사라진 상품)가 품목에 있으면 상세와 내려받기 검사에서 "파스토 목록에 없는 상품" 경고(막지는 않음).
- 받는 곳 표는 읽기 권한이 없으면 빈 결과가 오므로, 화면은 "볼 수 없음"과 "입력 안 됨"을 구분해 표시한다(요청자·담당자 여부로 판단).

## 8. 테스트

- 생성기: 양식 3종 각각 가짜 요청으로 행을 만들어 `tests/fixtures/fassto/` 원본과 1~4행·열 수·시트 이름 비교, 5행 값 검사(문자 상품코드, 같은 주문번호, 해외 무게 기본 1).
- 검사: 양식별 필수 칸 누락·금지 문자·FEDEX 이메일.
- DB(PGlite): 받는 곳 RLS(다른 직원은 0행), 품목 쓰기 권한·상태 규칙, 운송사는 담당자만, 주문번호 자동 생성·순번, 목록 교체 함수(권한·전체 교체).
- 화면: 운송 방식별 칸 표시, 품목 검색·수량 경고, 내려받기 버튼과 오류 표시.
- 운영 첫 사용: 김윤래님과 실제 요청 1건으로 내려받은 엑셀을 FMS에 올려 확인.
