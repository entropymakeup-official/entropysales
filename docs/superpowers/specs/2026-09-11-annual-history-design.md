# Annual inventory history design
Approved user intent: persist Wekeep daily history in Supabase and display calendar-year monthly statistics. No Wekeep API. Existing browser imports remain supported.

Preserve the current get/save_wekeep_history contract and product_window. Add private archive tables fed transactionally by a trigger on product_window insert/update. Retain an independent archive catalog so roster deletion does not erase history. Store one row per SKU/date, including a has_record=false marker for queried dates without source records; never turn those into numeric zeros. Keep collected_at per date; newer source queries may correct prior records, older cannot replace newer. Bootstrap existing windows idempotently with original collection times.

Expose authorized company-only get_wekeep_history_year(p_year integer). Response: {year,today,catalog:[{sku,name,code,supplier}],months:[{sku,month,covered_days,record_days,inbound,returned,faulty,damaged,outbound,balance,balance_date,last_collected_at,oldest_collected_at}],checked_at}. month is integer1..12. today is KST YYYY-MM-DD. covered_days counts observed date markers; record_days counts has_record true. Flow sums are null if no records, otherwise signed bigint sums. balance/balance_date only provided when source record exists on expected end (min(month end,today)); no summing balances or carrying prior value as month-end. Counts bounded to dates through today. Archive retains all years; UI requests one year, default current KST year. Year range 2000..current year. Archived catalog may include inactive products; keep historical identity.

UI adds inventory-monthly.js using existing InventoryHistory validators for imports and exact readback. Shows year/product selection, twelve monthly chart/table entries, flow sums and source coverage. Default all products; aggregate months counts expected product-days using catalog size and display incomplete conservatively (not necessarily existing at year start). Missing coverage, queried-but-no-record, partial current month and future month distinctly labeled. Display recorded subtotal with partial label when coverage incomplete. No unqueried month is displayed as zero. Current-month balances labeled latest as-of, historical exact month end only. No daily table by default. All-product aggregate balance only when every selected product has exact expected-date balance. Company authorization and private tables unchanged.

Verification: PGlite migration/repeat/retention/overlap/empty/monotonic/auth; JS leap years, year filters, signed sums, balances, unknown vs zero, escaping and async late results. Actual source January query feasible before promising full annual coverage. Deploy DB first, then UI; verify on company session. Backfill year months via browser pages and monthly imports. Initial incomplete data clearly shown until observed. Existing 10min collector updated to cycle current month plus backfill with durable state, preserving quiet notification intent.
