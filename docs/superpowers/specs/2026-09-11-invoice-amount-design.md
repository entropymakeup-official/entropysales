# 증빙 금액 보존

사용자는 검증한 다섯 주문을 세금계산서 공급가액으로 정정하도록 요청했다. 이전에 제시한 원본 금액과 출처를 보존해 집계에 반영하는 방향의 실행이다. 실제 거래 자료와 ID는 공개 저장소에 넣지 않는다.

기존 invoice_items에 nullable amount_override numeric(18,2), amount_reference text를 추가한다. 값과 출처는 함께 있어야 하며 확정 금액은 Paid 행에만 허용한다. null은 기존 qty×price를 사용하고 0 및 음수 금액도 숫자로 보존한다. 승인 요청/심사 체계와 회사 RLS는 그대로 적용한다.

대시보드 전체 집계, 인보이스/RAW 상세, 다운로드 및 시트 동기화는 override가 있으면 그 금액을 우선한다. 표시 단가와 수량은 변경하지 않는다. 주문 상세에서 증빙 금액과 근거를 편집/해제할 수 있으며 generic invoice_items update 승인 요청을 사용한다. 승인 전 확정 자료는 유지한다.

전체 주문 저장은 기존 증빙 행을 이름·바코드·판매유형·수량·단가가 모두 같은 유일 행으로 보존한다. 증빙이 있는 행을 변경하거나 모호한 중복으로 교체하려 하면 전체 저장을 거절하고 먼저 증빙 금액 해제를 요청하도록 안내한다. 헤더만 수정하는 요청은 증빙을 유지한다. 증빙이 있는 품목의 개별 값 변경에도 동일 보호를 적용한다.

서버 스키마, 기존 RPC 보존 및 Apps Script 단일 금액 산식 수정, 대시보드 배포를 함께 검증한 뒤 실제 다섯 주문을 현재값 조건의 승인 요청으로 수정한다. 사용자 요청은 실제 정정까지 포함하므로 재차 포괄 승인을 묻지 않는다. 운영 관리자 권한이 확인된 로그인과 정상 승인 UI로 처리한다. 권한이 없으면 요청을 준비하고 승인할 수 있는 주체를 확인한다.

가짜 업무 자료를 운영에 쓰지 않는다. 로컬 합성 검사로 기본값/0/음수/집계일치/승인전보존/승인후변경/재저장보존/품목변경거절/시트재전송을 검증한다. 실제 자료는 다섯 주문만 수정하고 기존 나머지 열/행 보존을 검증한다. 제품·담당자·재고·업무일자는 범위 밖이다.
