# 계약서 메뉴 구현 계획 (2026-09-17)

사용자가 승인한 채팅 설계: 거래처 마스터 아래 계약서 메뉴, 거래처별 복수 계약, 기간/갱신기한, 계약조건, 수금조건, FOC, 판매범위/독점, 구매약정, 담당자/특약, 기존 서류 연결, 이전 계약 연결. 기존 승인 체계를 유지한다.

- [ ] `contracts.js`, `tests/contracts.test.cjs`: 날짜 경계, 수금 비율·기준, FOC 입력 검사, 목록/폼, 요청 실패 시 입력 유지 및 승인 전 데이터 보존을 먼저 실패 테스트 후 구현.
- [ ] `sql/contracts.sql`, `tests/contracts-db.test.cjs`: contracts 테이블, FK와 CHECK, 회사 읽기 RLS, 직접쓰기 차단, 기존 승인 허용 테이블 확장. 독립 PGlite에서 승인 전/후, 외부 사용자, 충돌, 반려, FK, 제약 검증.
- [ ] `app.js`, `index.html`, `contracts.css`, `admin-approvals.js`, `admin.html`: 메뉴, 거래처 연결, 한국어 승인 비교 필드, 버전 캐시 통합.
- [ ] 전체 문법·회귀 테스트, 로컬 브라우저 합성자료 목록/등록/실패/모바일 점검. 운영 자료는 테스트 입력으로 사용하지 않는다.
- [ ] 최신 main 재확인, 리뷰, DB 추가 설치와 운영 배포, 읽기 검증 및 인수인계. 기존 업무행과 계약 원본은 수정하지 않는다.

저장: public.contracts의 명시적 컬럼으로 관리한다. 문서는 원본/변경합의서 FK, 이전계약 FK를 사용하고 삭제 RESTRICT. 확정 자료 변경은 ChangeRequests.row/submit 경유. 승인 이력이 변경감사 이력이다. 자동갱신은 표시 정보이며 기간을 자동 연장하지 않는다. 수금조건은 계약 약정이며 실제 입금값을 변경하지 않는다.
